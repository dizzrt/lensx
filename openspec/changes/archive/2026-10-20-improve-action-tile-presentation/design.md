# Design

## Context

动机和产品范围见 [proposal](proposal.md)，可观察行为见 [frontend-foundation delta](specs/frontend-foundation/spec.md)。本设计是待实施方案。

已检查的当前实现：

- `ActionTile.tsx` 被 `LauncherHome.tsx` 的两个集合及 `ActionSearchResults.tsx` 共用；标题使用 Semi `Typography.Text` 的单行 `ellipsis`，未配置全文提示。
- `global.less` 为首页指定八个等宽列，为 Search 指定可拉伸行高；tile 只有最小高度，按钮随容器拉伸。单独设置图标尺寸不能修正整个交互区域。
- 首页 Action 是可聚焦按钮；Search option 的 `tabIndex=-1`，输入框通过 `aria-activedescendant` 保持实际焦点。因此普通按钮 `focus` 监听无法覆盖键盘选择的搜索结果。
- 现有文档规定 Home / Search 固定 `650×320` / `650×480`，Search 四列最多八项，首页集合各最多八项；原生窗口不接受 DOM 文本尺寸作为调整依据。
- 当前测试已有 Home 执行、Search 选择与执行、IME 和焦点覆盖。Rstest 的 DOM 环境不提供可信的真实文字排版度量。

本变更涉及共享组件、布局、DOM 测量生命周期及两种焦点模式；这些耦合需要明确设计，而不是仅调整一条样式。

## Goals / Non-Goals

**Goals:**

- 在共享展示层统一几何和适配规则，同时保留不同界面的列数与交互语义。
- 将字号计算、尺寸读取与浮层候选管理分开，使计算和生命周期能进行确定性测试。
- 只增加当前 Host 前端所需的少量逻辑，复用 Semi Button、Typography、Tooltip 及现有主题。

**Non-Goals:**

- 不改 Registry、Dispatcher、搜索排序、Rust 服务或插件契约，不持久化字号与提示状态。
- 不建立通用排版库、全局浮层框架、字体设置或跨插件的提示服务。
- 不把真实浏览器、WebView 或截图比较纳入验证流程。

## Decisions

### 1. 在既有 frontend-foundation 内补充共享展示契约

Recent、Pinned 和 Search 共用三个新增要求：方形交互区域、有界单行标题和截断全文提示。保留 `launcher-action-collections` 与 `launcher-action-search` 的现有要求；无需复制它们的排序、身份和执行章节。

相比创建相似的新 capability，这使共享 App Shell 展示规则继续由现有规范持有。同步阶段只追加新增要求，不替换或遗漏已有 requirement。

### 2. 用列宽决定方形，不让行高决定卡片外形

保留首页八列和 Search 四列。tile 以当前列宽作为边长，使用 CSS 宽高比和明确的非拉伸对齐；清理会覆盖方形约束的行高、最小高度及按钮尺寸组合。按钮填满 tile，图标与单行标题在方形内作为固定结构居中。

继续使用现有 `28px` 图标和 `12px` 圆角；标题行盒固定为 `20px`，字号适配不改变行盒、图标或网格位置。现有宽度下，Home 边长约 `70.25px`、Search 约 `148.5px`；这些是空间核算，不是新的固定尺寸契约。图标、行盒、间距和内边距须共同落在方形内。

简单网格和对齐继续使用 UnoCSS；方形、标题截断、按钮状态及浮层相关的可复用语义放在 Less。hover/focus/selected 仅改变既有状态表现，不增加静态卡片背景。

不选择“只给图标加方形背景”，因为用户要求的是整个 Action；也不扩大原生窗口或减少列数来容纳标题。

### 3. 按实际宽度计算连续字号，以有界校正处理度量差异

新增 Host 私有的标题适配 helper/hook，职责限于当前 Action 标题：

1. 读取标题行盒的有效内宽，以及在 `14px` 基准下完整文本的宽度。基准使用实际 font family、weight、letter spacing 等排版属性，不能读取已经省略的字符串或按字符数估算。
2. 基准宽度不超出可用宽度时直接使用 `14px`；否则按宽度比例计算候选字号，并限制在 `[12, 14]`。
3. 按候选字号复核完整文本。若字体形状、字距或小数舍入导致偏差，用有界校正寻找可容纳的字号，不轮询固定的 `14 → 13 → 12` 档位；在边界附近允许至多 `0.1px` 的字号精度误差。
4. 在 `12px` 下仍超宽时保留最小字号，并将 `isTruncated` 置为 true；可见文本采用 CSS 单行末尾省略。恰好容纳时不算截断。

测量采用不参与正常布局、`aria-hidden`、不可聚焦的完整文本测量节点，与可见标题共享排版属性；测量节点不使用 `display:none`，并独立于当前可见字号，避免在上次缩小的结果上反复缩小。默认基准是 `14px`，比例候选与有限校正均在测量节点完成；一次提交最终字号和截断状态，不向用户展示逐步试字号。

`font-size`、固定行高及 CSS ellipsis 只有一套所有者；不让 Semi 的 JavaScript 截断先移除字符再交给适配器测量。可继续使用 Typography 的语义与主题，但通过项目样式管理可见单行截断，完整标题原文始终可获取。

不选仅依赖 `clamp()`，因为它不根据文本溢出求字号；也不依赖实验性 `text-fit`。本方案不要求提升 macOS WebView 的能力基线，不引入第三方适配库。可参考 [clamp 定义](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp) 和 [text-fit 兼容记录](https://github.com/mdn/browser-compat-data/blob/main/css/properties/text-fit.json)，实现不依赖这些页面的后续变动。

### 4. 测量只随实际输入变化，失败时安全恢复

标题原文或语言更新、标题容器宽度变化、字体就绪和后续字体加载完成均使测量失效。使用 `ResizeObserver` 观察可用宽度；通过字体加载事件及首次就绪通知刷新度量。普通 hover/selection 只控制提示，不反复测量文字。

同一帧合并重复通知，只有结果实际变化时才提交状态，观察对象不受文本字号撑宽。清理 observer、事件监听和排队任务；异步字体通知通过组件存活／测量版本检查避免写回已卸载或已替换的标题。

零宽、非有限尺寸、未布局或测量失败时使用 `14px` 单行 CSS 溢出保护并保留完整可访问名称；不把无效测量标记为永久截断，不展示伪造的截断提示。下一次有效布局、标题或字体通知恢复正常计算，不抛出会阻断 Action 的错误，也不新增错误文案。

纯计算逻辑接受可控宽度和测量函数；DOM hook 负责实际读取。测试可以固定度量验证算法与失效处理，不需要真实字体环境。

### 5. 用受控 Semi Tooltip 统一鼠标与键盘候选

每个 Home / Search 实例持有局部提示协调状态；Home 的两个集合共享一份协调状态，不增加应用级 Provider。每个 tile 提供实例身份、完整标题、截断状态及锚点。提示实例身份必须区分 Recent 与 Pinned 中相同 `action_id` 的两次出现。

候选优先级为：

1. 当前指针所在的 tile，或指针正在阅读的该 tile 提示；
2. Home 当前获得键盘焦点的主按钮；
3. Search 输入框保持焦点时的当前 selected option，包括默认首项。

先选候选，再判断其是否截断。因此指针进入完整显示的短标题时，应隐藏另一个键盘候选的提示；离开后恢复仍有效的键盘候选。同一界面最多呈现一个提示。

候选使用受控 Semi Tooltip 展示完整文本。指针从 tile 移入提示时保持提示可见；离开两者后重新仲裁。提示挂载到 body overlay 层，避免 tile 或 App Shell 的 `overflow:hidden` 裁切；宽度受窗口约束，长连续词允许换行，极端长内容需要限制高度并保持内容可访问。不得新增执行、复制或关闭按钮。

保留完整标题作为按钮／option 的可访问名称，测量节点不参与命名。Tooltip 关联使用实例唯一标识，不能覆盖搜索框已有的状态区 `aria-describedby`，也不能把 selected option 改为真实 DOM 焦点。正文由当前标题元数据解析，不产生替代名称或重复产品文案。

首页 Escape 关闭当前提示并抑制同一触发周期的自动重开，直到指针或焦点重新进入有效触发条件。Search Tooltip 不自行处理 Escape、Enter 或方向键：保持既有输入处理，Escape 一次清空搜索并卸载提示，IME 组合／确认仍优先。失焦清理键盘候选；查询清空、卡片移除、界面切换、标题不再截断和卸载均清理失效提示。

只开启 Typography 的 `showTooltip` 无法覆盖 Search 的 active descendant 及跨集合候选仲裁，因此采用受控 Tooltip；不使用原生 `title` 作为唯一提示方式。当前 pending 禁用逻辑继续保留，指针候选可由非聚焦的 tile 包装层感知，不添加额外 Tab 停靠点。

### 6. 复用现有验证入口并记录证据边界

在现有 `tests/**/*.test.{ts,tsx}` 下加入适配 helper 与共享组件测试，扩展 Home / Search 测试。新增测试由 `pnpm run test` 自动发现；复用 `pnpm run gate -- launcher-input-focus` 检查 Search、IME 和焦点链路回归。该 Gate 不替代完整测试集，也不需要为了此次变更新增 Gate 或根脚本。

字号案例覆盖最大值、中间非整数值、最小值仍超宽、恰好容纳、中英文、字体变化、零宽恢复及有界校正。组件测试注入可控文字尺寸、容器尺寸与字体／observer 通知，检查单行、省略、可访问名称、更新和清理。样式约束检查覆盖方形及非拉伸组合，不将 DOM stub 的尺寸声明为真实排版证据。

提示测试覆盖 Home 两个集合、重复 Action 实例、Search 默认选择／箭头选择、hover 优先与恢复、输入框失焦、语言切换、清空与卸载、两种主题及 pending 执行去重。沿用真实 Semi 组件进行交互测试；尺寸相关能力做局部、可恢复的替身。

## Risks / Trade-offs

- 字体度量随字体就绪或排版属性变化 → 使用同排版属性的完整文本节点、固定基准、失效重算与有限校正，禁止累积缩放。
- 相邻标题可能使用不同字号 → 只允许 `12–14px`，固定行盒和图标位置；完整标题能容纳时保持最大字号。
- Search 方形高度增加，或首页行被拉伸 → 明确清理冲突的行高和最小尺寸，覆盖满八项和错误／pending 布局状态；不借由窗口扩展掩盖问题。
- Tooltip 与输入交互争夺焦点或 Escape → 单一受控候选，保留输入处理优先级及既有 ARIA 关联，测试实际 Semi 交互。
- 浮层越界或重复显示 → 使用窗口内定位和 body portal，限制浮层尺寸；Recent/Pinned 共同仲裁且实例标识唯一。
- 确定性测试无法证明平台字体的最终像素外观 → 记录其仅证明计算、样式约束和交互契约；不新增浏览器、真实 WebView、截图或性能验收路径。

## Migration Plan

仅前端展示和文档更新，无数据迁移或新依赖。未来 apply 先交付共享适配逻辑与方形布局，再集成提示和回归测试，随后更新英文文档及中文镜像并完成验证。

如需回滚，恢复共享 tile、样式及局部提示／测量逻辑即可，Action ID、标题原文、集合持久化与执行目标不变。稳定规格同步前完成最终范围核对；同步与归档须按后续授权及既有流程执行，本轮不执行。
