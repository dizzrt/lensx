## Why

当前 launcher 使用无系统标题栏的透明、无边框窗口，但顶部统一区域没有可用的拖窗手势，用户无法从搜索框、头像或周围空白处自然地移动窗口。需要让截图所示的完整顶部区域承担自定义标题栏职责，同时避免破坏 launcher 以搜索输入为核心的聚焦、输入和页面关闭交互。

## What Changes

- 让 `home`、`search` 和 `page` 三种展示状态的完整顶部区域支持使用主鼠标按键拖动原生窗口，包括顶部空白、搜索框、页面上下文的非操作区域和装饰头像。
- 对搜索框协调点击与拖动手势：不移动的单击继续聚焦输入并定位光标，拖动手势移动窗口，键盘输入、输入法组合和键盘选择保持可用。
- 将页面上下文中的关闭按钮排除在拖动手势之外，使其继续可靠地关闭页面并恢复搜索框焦点。
- 保持头像为不可点击、不可聚焦且不提供账户功能的装饰元素；支持拖窗不会赋予它新的产品语义。
- 通过受限、可测试的 Tauri 窗口拖动边界执行原生操作，并仅向主窗口授予所需的最小权限。
- 增加前端交互测试、能力配置检查和 macOS 原生拖动验收；保持现有连续表面样式及 `650px` 固定宽度、`320/480/600px` 离散高度不变。

### Goals

- 让用户从视觉上属于顶部区域的任意非排除位置移动 launcher 窗口。
- 在搜索框拖窗能力与现有键盘优先、自动聚焦和可访问交互之间建立明确且可验证的仲裁规则。
- 复用现有 React/Tauri 架构边界，不引入新的运行时依赖或组件库。

### Non-goals

- 不增加窗口缩放、最大化、最小化或新的窗口控制按钮。
- 不改变 launcher 的展示状态、原生尺寸、位置持久化、自动隐藏或全局快捷键行为。
- 不让头像、页面上下文文字或顶部空白变成可访问操作控件。
- 不保证在搜索框内用同一主鼠标拖动手势进行文本范围选择；窗口拖动与鼠标拖选冲突时，窗口拖动优先，文本仍可通过单击定位和键盘选择。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `launcher-window-lifecycle`: 增加无边框 launcher 顶部区域发起原生窗口拖动的行为、排除区域、失败恢复与固定窗口形状约束。
- `frontend-foundation`: 扩展统一顶部区域的交互要求，使搜索输入、页面上下文、装饰头像和关闭按钮在拖窗手势下保持既有语义与键盘行为。

## Impact

- 前端 App Shell 顶部区域的 DOM 结构、指针事件协调、窗口拖动客户端边界及相关 Rstest/Testing Library 测试。
- Tauri 主窗口 capability 权限，以及用于验证最小授权和原生拖动失败的配置或边界测试。
- `launcher-window-lifecycle` 与 `frontend-foundation` 的稳定要求，以及相关英文文档和简体中文镜像。
- macOS 原生运行时验收，包括顶部空白、搜索框、头像和页面状态下的拖动与交互回归检查。
