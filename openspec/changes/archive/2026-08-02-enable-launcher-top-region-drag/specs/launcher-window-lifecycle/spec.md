## ADDED Requirements

### Requirement: launcher 统一顶部区域必须支持原生窗口拖动

系统 MUST 允许用户在 `home`、`search` 和 `page` 展示状态下，使用主鼠标按键从 launcher 的完整统一顶部区域发起原生主窗口拖动。该区域 MUST 横跨窗口宽度，并从窗口上边缘延伸至统一顶部槽的下边缘，包含顶部空白、搜索输入、页面上下文的非操作区域和装饰头像。拖动 MUST 通过受限的 Host 窗口边界执行，且 MUST NOT 允许前端提交窗口坐标、任意尺寸、缩放或最大化请求。

页面上下文的关闭按钮及任何显式排除的操作控件 MUST NOT 发起窗口拖动。辅助鼠标按键和键盘事件 MUST NOT 发起窗口拖动。拖动成功或失败 MUST NOT 改变当前展示状态、查询、Action 选择、活动页面或固定窗口形状。

#### Scenario: 从 home 顶部空白移动窗口

- **WHEN** launcher 处于 `home` 状态且用户使用主鼠标按键拖动统一顶部区域的空白位置
- **THEN** Host 发起原生主窗口拖动
- **THEN** 主窗口保持 `650×320px` 的逻辑尺寸

#### Scenario: 从 search 输入区域移动窗口

- **WHEN** launcher 处于 `search` 状态且用户使用主鼠标按键从搜索输入区域发起拖动
- **THEN** Host 发起原生主窗口拖动
- **THEN** 当前查询、搜索结果和 Action 选择保持不变
- **THEN** 主窗口保持 `650×480px` 的逻辑尺寸

#### Scenario: 从装饰头像移动窗口

- **WHEN** 用户使用主鼠标按键拖动统一顶部区域最右侧的装饰头像
- **THEN** Host 发起原生主窗口拖动
- **THEN** 头像不触发账户、菜单、导航或其他产品操作

#### Scenario: 从页面上下文非操作区域移动窗口

- **WHEN** launcher 处于 `page` 状态且用户拖动页面上下文文字或其周围空白
- **THEN** Host 发起原生主窗口拖动
- **THEN** 活动页面保持打开且主窗口保持 `650×600px` 的逻辑尺寸

#### Scenario: 操作页面关闭按钮

- **WHEN** launcher 处于 `page` 状态且用户使用主鼠标按键激活页面上下文关闭按钮
- **THEN** 系统不发起窗口拖动
- **THEN** 系统关闭活动页面并返回 `home` 状态

#### Scenario: 使用非主鼠标按键或键盘

- **WHEN** 用户在统一顶部区域使用辅助鼠标按键、右键或键盘事件
- **THEN** 系统不发起窗口拖动
- **THEN** 当前 launcher 状态保持不变

#### Scenario: 原生拖动请求失败

- **WHEN** Host 无法开始原生窗口拖动
- **THEN** 当前窗口位置和固定形状保持在最后成功状态
- **THEN** 当前查询、Action 选择、展示状态和活动页面保持不变
- **THEN** 失败可供开发诊断且不会向用户暴露原生错误细节
