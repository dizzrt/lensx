# Proposal

## Why

当前 macOS 被动输入监听在重建、部分创建失败和退出时只移除 RunLoop source 并释放引用，缺少显式端口失效操作；现场出现 LensX 累积 264 个监听、退出后全部消失且桌面恢复流畅的现象，与这一资源生命周期缺陷高度吻合。需要补齐完整清理和可验证的恢复边界，防止长期运行中旧监听持续积累；具体中断触发频次和系统卡顿机理仍不能仅由静态检查证明。

## What Changes

- 为 macOS 被动监听建立唯一资源所有权，完整覆盖正常停止、故障重建、不再需要监听、权限或可观察性丢失、部分创建失败的清理。
- 在重建前完成旧监听注销；保留健康监听跨手势、配置和录制状态重置的既有行为，维持恢复重试节拍与停止后的禁止重建约束。
- 保留监听不可用时清除候选、唯一 Launcher 双击入口失效时显示窗口、普通组合键独立工作及原始输入透传的现有契约。
- 在现有 `launcher-shortcuts` Gate 中加入确定性资源生命周期回归：反复恢复不增长、部分失败无残留、重复清理不重复释放、停止后资源归零。
- 同步现有英文架构和验证章节及简体中文镜像，明确资源所有权和确定性验证的证明边界。

### 目标与用户影响

长期运行和反复中断恢复后，Host 最多保留一个当前被动监听，已退休监听不再保留系统注册；监听恢复后按新的输入序列继续识别，不误触发旧手势。现有快捷键设置、交互、权限提示和恢复入口保持兼容。

### 非目标

- 不增加新的快捷键能力、配置版本、Tauri/SDK API 或运行时依赖。
- 不重构快捷键持久化锁或异步分发架构；回调等待服务锁属于已识别的潜在放大因素，本次不将其认定为现场根因。
- 不改变 10 ms 轮询节拍、手势时间阈值或权限申请策略，不绕过 Secure Input。
- 不新增 GUI、真实 WebView、原生交互 harness、性能基线或环境验收 Gate；不承诺仅靠确定性测试证明整机卡顿完全消除。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `launcher-shortcuts`：新增被动输入监听资源有界所有权、完整注销和恢复生命周期要求，补足现有监控授权与故障恢复契约未明确的原生资源边界。

## Impact

- Rust：主要涉及 `src-tauri/src/launcher_shortcuts/macos.rs` 及必要的同模块生命周期抽象和测试；复用 `service.rs`、`mod.rs` 中现有可用性与恢复发布边界。
- 测试：纯资源后端、虚拟时间和已有服务/恢复测试覆盖实际生产生命周期路径，复用 `pnpm run gate -- launcher-shortcuts`，不添加根脚本或独立 Change Gate。
- 文档：实施时更新 `docs/en/architecture/overview.md`、`docs/en/development/validation.md` 和对应 `docs/zh/` 文件；无需新增文档或修改导航。
- 兼容性：不改变已存储配置、跨边界 payload、用户文案、主题和语言；保留英语默认及简体中文、键盘操作、焦点与恢复可访问性。
- 本提案只创建规划产物；实现、稳定规格同步和归档分别在后续授权阶段完成。
