# Design

## Context

动机和已确认范围见 [proposal.md](proposal.md)。当前 `src-tauri/src/launcher_shortcuts/macos.rs` 在一个后台线程中维护 listen-only session tap、RunLoop source、回调 `Context` 及睡眠/唤醒通知订阅；正常初始化受 Launcher setup 防重复保护。

当前生命周期存在三个清理出口：运行中替换/撤销、tap 创建成功而 source 创建失败、线程正常结束。这些路径均未显式调用 `CFMachPortInvalidate`；Apple 的 [CFMachPort 文档](https://developer.apple.com/documentation/corefoundation/cfmachport) 要求在释放 source 和 port 前使端口失效。仅移除 source 和降低引用计数不能作为已完成系统注销的保证。

观察循环已区分手势 epoch 重置与真实监听中断，健康 tap 在仍有需求时不因普通隐藏或录制结束而重建。创建尝试已有一秒节流，空循环通过锁外 10 ms 等待限制轮询。当前测试覆盖手势、状态降级和等待节拍，尚无使用生产资源管理路径的原生注销与计数回归。

## Goals / Non-Goals

**Goals:**

- 使原生注册、引用、回调状态和通知订阅的所有权边界明确，所有退出路径遵循相同终止规则。
- 将可确定验证的资源生命周期从平台调用中分离，生产适配器与 fake 后端共用所有者及状态转换。
- 在原生资源尚未准备完整或已失效时保守发布可用性，维护唯一双击入口的可恢复性。

**Non-Goals:**

- 不改变服务存储事务、事件处理锁、主线程任务分发或跨边界 payload；不新增 SDK、Tauri 命令、持久化字段或依赖。
- 不增加真实系统事件驱动的验证入口；不将现场监听数量与卡顿关联升级为已证明的系统内部因果链。
- 不调整轮询、手势阈值、权限提示或快捷键 UX；既有 i18n、主题、键盘与焦点契约由现有 Gate 回归。

## Decisions

### 1. 使用绑定观察线程的唯一资源所有者

在 `launcher_shortcuts` 内部建立小型可注入原生操作的资源所有者，平台实现仍留在 macOS 适配器。所有者持有当前 tap、可选 source、其所属 RunLoop 以及是否已附加 source 的事实；句柄不得复制、跨线程转移或暴露给 React/插件。循环只保存零个或一个所有者。通过 Create 取得的 tap/source 引用需要对称释放；所属线程的当前 RunLoop 是借用引用，不作为新取得的受管引用释放。

tap 一旦创建即进入受管状态，source 创建失败直接销毁该部分构造的所有者。只有 source 已建立并附加、tap 确认 enabled 后，尝试才被视为 Active。健康监听保持同一所有者，不通过重建完成普通识别状态重置。

回调 `Context` 先于资源所有者建立，并保持有效直至 tap 已失效且 source 已移除；正常退出及 Rust unwind 均先清理监听，再释放回调状态。睡眠/唤醒通知 token 使用作用域所有权，在线程退出或 unwind 时移除订阅，避免遗留的通知闭包继续保留 app/state。资源析构只执行原生清理，不再次获取快捷键服务 mutex，也不等待主线程或发起业务事件。

备选是逐个出口补一个 FFI 调用；它能修复当前三处遗漏，但不能约束后续提前返回和 unwind，且难以直接验证生产所有权。选择集中所有者与最小操作接口，不引入通用平台框架。

### 2. 统一、幂等的终止顺序

正常终止、重建、不可观察、无需监听以及部分失败均使用同一个清理入口：

1. 从循环中取走当前所有者，确保重复清理不能再次操作同一组句柄；在实际失效路径先撤销 monitor admission 并清候选。
2. 对成功创建的 tap 调用 `CFMachPortInvalidate`，终止端口消息和关联 source。
3. 如果 source 已附加，使用原所属 RunLoop 和 mode 移除；仅对已创建的 source 释放一次引用。
4. 对 tap 释放一次引用，再允许回调状态结束或后续创建新 tap。

未创建成功的句柄不清理，部分资源不假装完整，显式清理后的 `Drop` 无额外效果。`CGEventTapEnable(false)` 不是注销替代品；本次不改变系统禁用后通过受控重建恢复的策略。

停止、锁中毒等线程提前退出也通过所有者析构收尾。异常退出必须撤销独立发布的 monitor admission；服务仍可用时更新 `MonitorStatus`，无法取得健康服务状态时也不得留下 Active 的可恢复性事实，并通过既有恢复边界保留修复/退出可访问性。清理本身不能依赖再次成功取得服务锁。

### 3. 将资源状态转换与识别状态重置分开

| 输入事实 | 原生资源行为 | 状态与输入行为 |
| --- | --- | --- |
| 仍需观察且监听健康，只有配置/录制/手势 epoch 变化 | 保留同一所有者 | 清候选；不制造假监控故障 |
| tap 禁用、callback interruption、既有运行间隔异常判定 | 完整终止旧所有者，再经过重试门限创建 | 先撤销可用性；不回放旧候选 |
| 权限丢失、Secure Input、睡眠或不再需要监听 | 完整终止；不在禁止条件下创建 | 保留既有 PermissionRequired / Unavailable 区分及恢复策略 |
| 条件恢复且符合重试门限 | 最多一次在途同步创建；失败立即收尾 | 新采样物理状态，完整成功后才 Active |
| 已停止或线程无法继续 | 完整收尾且不再创建 | 撤销监控可用性，旧事件不执行 |

重试使用既有单调时钟 `Instant`：首次符合条件即可尝试，其后两次尝试至少相隔一秒；不添加后台重试任务或队列。保留锁外 10 ms 等待及队列输入先于 quiet confirmation 的顺序。共享服务健康且故障仅限于被动监听时，普通组合键注册与被动监听授权继续独立；共享服务锁中毒时保守降级并保留可见修复/退出入口，不在本次重建共享服务。

新监听继续使用 session-level、listen-only 参数，不读取文本、不吞事件、不合成输入。先清理旧资源再创建新资源允许真实故障期间短暂 Unavailable；唯一 Launcher 双击失效时沿用现有显示窗口、禁止不可恢复隐藏、不注册隐藏 fallback 的恢复策略。

备选是每次系统禁用时直接重新启用原 tap；这需要重新定义不同中断原因的有效性和重启语义，对本次清理修复无必要。保持现有重建条件与节拍，先保证任何原因的重建都不积累旧注册。

### 4. 以确定性后端验证生产路径

资源所有者和控制器测试放在 `launcher_shortcuts` 模块，直接由既有 `cargo test ... launcher_shortcuts` 发现。fake 后端分别记录系统注册、持有引用、source 附加状态及回调上下文存活期；单纯释放引用不得被 fake 当作完成系统注销，以便遗漏 invalidate 时测试确实失败。虚拟时钟驱动重试与状态转换，不调用真实系统监听、权限、睡眠或 GUI。

至少覆盖以下矩阵：

| 场景 | 核心断言 |
| --- | --- |
| 正常创建、健康轮询、停止 | 系统注册及 tap/source 持有量不超过一；注销发生在引用释放前；停止后全归零 |
| tap 失败、source 失败、创建后未启用 | 已取得资源逐一终止释放；不发布 Active；无半初始化残留 |
| 空所有者和重复 cleanup / Drop | 不重复注销或释放，不访问无效句柄 |
| 各种实际中断与恢复 | 旧注册终止早于新建；旧候选/回调不能影响新序列 |
| 至少 1000 次混合故障恢复 | 任意时点最大注册数不超过一，已退休资源无残留，最终分配与释放计数平衡 |
| 仅配置/录制/隐藏/手势重置 | 仍需监听时资源 identity 不变，无额外 create/invalidate |
| 一秒节流边界和无 source 轮询 | 时间未到不尝试，到期至多一次；既有 10 ms 等待测试继续通过 |
| 停止、锁损坏退出、受控 Rust unwind | 先撤销可用性并完整清理，再允许上下文释放；停止后不重建，通知 token 解除 |
| sole-double-tap 失败与恢复、普通 chord | 失败继续保留修复入口，成功后才恢复双击；无 fallback；共享服务健康且仅监听失败时普通 chord 独立 |

计数和操作顺序针对生产资源所有者，不另写只在测试中运行的模拟清理算法。资源与状态交接可在 Rust 单测中完成；不为它增加根脚本、独立 Gate、Generate target 或依赖。复用 `pnpm run gate -- launcher-shortcuts`，并保留全部 frontend/workspace 与 Rust 最终检查。

### 5. 文档与规格保持原有归属

实施时在现有 `docs/en/architecture/overview.md` 的 configurable shortcuts 章节记录所有权、终止顺序和恢复边界，在 `docs/en/development/validation.md` 的 Configurable Shortcut Validation 章节记录新增覆盖与证明限制，同时同步两个 `docs/zh/` 镜像。不新增文档目录、导航或重复目录。接受的增量进入稳定规格前改写为英文；规划阶段不提前修改稳定规格。

## Risks / Trade-offs

- 原生句柄重复释放或回调状态过早释放 → 唯一所有权、显式部分构造状态、幂等 take，以及清理顺序和上下文存活期测试。
- 析构在持锁 unwind 中再次请求同一服务锁而死锁 → 原生资源析构与业务状态发布分离，析构不获取服务锁。
- 真实不可用与普通 gesture reset 混淆，误伤唯一双击恢复入口 → 以转换表明确处理原因，保留健康 identity，并复用现有恢复回归。
- fake 证明了 API 调用和资源约束，但不能证明实际 macOS 长期性能或具体禁用频次 → 文档和验证记录明确该边界，不引入环境性能 Gate，不将计划验证写成已通过证据。
- 进程强制终止或 abort 无法依赖 Rust `Drop` → 本次保证应用可控制的正常退出、显式停止和 Rust unwind；不可执行用户清理代码的终止由操作系统回收，不承诺执行应用析构。
- 事件回调仍可能等待服务锁，继续出现真实中断 → 先保证反复恢复无泄漏；锁架构优化不并入本次修复，也不以消除所有中断作为验收条件。

## Migration Plan

无需配置、磁盘数据或公开协议迁移。后续实施完成并通过确定性验证后，按既有打包流程分发修复版本；本 Change 不执行打包、部署或替换正在运行的应用。

已运行进程中的历史残留句柄不能由新所有者接管，使用修复构建前需完整退出旧进程，再正常启动。若需回滚，可恢复旧应用构建而无需回滚配置，但旧构建仍有已识别的泄漏风险；该风险应保留在变更说明中。
