## Why

当前应用已经具备统一的颜色主题与语言 Provider，但偏好只存在于前端运行时，用户无法在产品内查看、修改并跨启动保留这些设置。同时，“设置”属于 Host 自身能力，如果继续沿用内置插件模型，会混淆应用能力与插件运行时边界。

本次变更需要在现有单一 Tauri 主窗口中提供设置入口与设置页面，并以最小范围补齐 App Shell 从主页/搜索状态进入 Host 页面、再返回主页的能力。

## What Changes

- 新增 Host 自有的“设置”Action；它可以参与现有 Action 搜索，但不注册为插件。
- 在现有主窗口的公共内容区域展示设置页面，不创建独立 Tauri 设置窗口。
- 为 App Shell 增加最小页面态：
  - 无活动页面且查询为空时展示主页内容区域；
  - 无活动页面且查询非空时展示搜索结果；
  - 活动页面存在时，顶部搜索输入替换为不可搜索的页面上下文头部，显示能力名称、Action 名称与返回主页的关闭按钮，公共内容区域展示对应页面。
- 主窗口根据 `home`、`search`、`page` 三种呈现状态使用 Host 控制的固定离散高度，
  确保公共内容区可见；不根据结果数量或 DOM 测量连续调整窗口。
- 设置第一版包含“偏好”和“插件”两个一级部分：
  - “偏好”支持 `light` / `dark` 颜色主题切换；
  - “偏好”支持 `en-US` / `zh-CN` 语言切换；
  - “插件”仅展示空占位，不提供插件管理行为。
- 新增 Host 偏好持久化边界；应用启动时恢复主题与语言，更新成功后同步现有主题与国际化 Provider。
- 页面打开前若目标不可用，则保留当前主页/搜索状态与查询并显示安全反馈；页面进入后发生加载或渲染失败时，保留页面头部和关闭能力，在公共内容区域展示错误状态。
- 保持现有 Action executor 签名，由受信任的 Host executor 调用最小的、与 React 无关的页面导航服务。

本次变更不引入通用路由器、导航历史栈、新状态管理框架、插件运行时或插件管理功能，也不新增最近使用、固定项目等主页数据能力。

## Capabilities

### New Capabilities

- `host-settings`: 定义 Host 设置 Action、单窗口设置页面、偏好项、插件空占位、偏好持久化以及设置页面的失败处理。

### Modified Capabilities

- `frontend-foundation`: 扩展 App Shell 的主页/搜索/页面呈现状态，并让现有主题与语言 Provider 从持久化偏好初始化和更新。
- `launcher-action-core`: 将打开设置作为默认 Host Action，并明确受信任 executor 通过最小导航服务打开 Host 页面。
- `launcher-window-lifecycle`: 将单一 180px 高度扩展为由 Rust 校验的
  `home` / `search` / `page` 离散呈现高度，同时保持固定宽度、不可手动缩放和
  非内容测量边界。

## Impact

- 前端 App Shell、主题 Provider、国际化 Provider、Action 注册与页面组合会发生变化。
- Rust/Tauri 层新增稳定、可序列化的偏好读取/写入命令、持久化实现，以及受约束的
  launcher 呈现高度命令。
- 需要新增前端与 Rust 测试，覆盖页面状态切换、Action 打开设置、主题/语言恢复与更新、持久化失败和页面失败。
- 需要更新英文架构/前端文档及对应的简体中文镜像。
- 外部插件清单与插件生命周期契约不发生变化。
