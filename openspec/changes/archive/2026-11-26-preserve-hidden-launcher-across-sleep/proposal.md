# Proposal

## Why

macOS 上，用户在 lensX 已经隐藏时锁屏、合盖，回来后可能看到上一次使用的翻译页。现有 Host 在睡眠时会把 Launcher 快捷键暂时标记为不可用，状态变化可能触发原本用于修复快捷键故障的主动显窗；这条路径无需用户按键即可恢复之前的插件窗口。

## What Changes

- 锁屏、睡眠以及恢复输入的过程应保留已隐藏的主窗口和插件页面。系统通知和过期的修复请求都不能激活应用、切换页面或抢占键盘焦点。
- 用户恢复使用电脑后，普通 Launcher 快捷键继续恢复原页面和输入；只有一次新的、有效的专属 Action 快捷键才能以快捷键来源执行该 Action。
- 当用户回到可交互会话，若确认唯一的主窗口快捷键确实失效，Host 须让修复和退出入口可见。若系统没有提供足够的桌面交互证据，用户可以通过 Finder 重新打开仍在运行的 lensX 进入修复。单个插件的双击监听中断不能使正常工作的主窗口组合键失效。
- 范围限于 macOS Host 的快捷键恢复与主窗口生命周期。插件业务、独立窗口交互、快捷键配置格式、首次启动展示和其他平台沿用既有契约。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `launcher-window-lifecycle` — 界定何时允许为修复而自动显示主窗口，以及何时应保持隐藏直到用户主动唤出。
- `launcher-shortcuts` — 区分会话暂时中断、当前入口已恢复和已确认的入口故障，约束中断前后的按键、回调与修复请求。

## Impact

主要涉及 Rust 的 `launcher_shortcuts`、macOS 通知适配和统一窗口动作边界，复用现有窗口显示与插件视图恢复顺序。实现时同步英中架构与验证文档，并在现有 `launcher-shortcuts` Gate 内覆盖状态变化和实际窗口效果。翻译页用作保留当前插件实例的验收样例。此次变更无需配置迁移、插件升级或新的用户权限。
