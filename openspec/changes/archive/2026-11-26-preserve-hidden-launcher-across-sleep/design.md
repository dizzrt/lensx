# Design

## Context

`launcher_shortcuts/macos.rs` 在系统休眠和唤醒时清空手势并撤销输入监听。`ShortcutAdmission` 在睡眠期间把主快捷键标为不可用于恢复窗口，`publish_monitor_snapshot` 可将这一状态送入 `ensure_recovery_visible`。后者执行 `Show(Programmatic)`，从而激活应用、显示主窗口并恢复当前插件视图。该路径足以解释用户看到上次隐藏的翻译页。另有专属快捷键通过 `Effect::Action` 执行插件，两者需要分别控制。动机见 [proposal.md](proposal.md)。

## Goals / Non-Goals

Rust 分别判断现在能否接受输入、主窗口的唯一唤出入口是否需要修复、当前会话是否适合显示修复窗口。React 继续持有页面及输入，插件、独立窗口和公开协议沿用既有边界。首次启动展示、持久化配置、其他平台和插件业务均不在变更范围内。

## Decisions

### 根据主窗口快捷键的实际故障决定是否修复

快捷键服务保留现有无锁输入资格检查。另行根据选中的 Launcher 绑定评估修复需求，供窗口边界使用。睡眠、安全输入、事件监听正常撤销或重建期间，只清除候选手势、录制与旧输入，允许正常失焦隐藏。主入口是普通组合键时，按其实际注册状态判断；其他 Action 的双击监听丢失只影响相应 Action。

会话恢复后重新读取配置和注册结果。当前 Launcher 注册确实失败、配置迁移未解决、补偿结果不确定，或者作为唯一入口的双击缺少已复核的输入监控授权，均可触发修复。双击监听重建应先走现有重试机制，在相同配置、已获许可且可观察的条件下重新建立仍然失败，才可判定故障。单独的 `Unavailable`、经过一段时间或收到一次唤醒通知都不足以升级故障。若恢复成功，撤销待修复状态。

### 等到有当前桌面可以交互的证据

由 Rust 的 macOS 适配层通过现有 AppKit 依赖管理会话观察。系统睡眠、显示器休眠、会话切出与安全输入分别处理；进入中断撤销之前的可交互证据。电源唤醒、亮屏、会话切入或安全输入结束只触发复核。多个原因可以重叠，解除其中一个不能清除其他原因。

会话观察独立于被动输入监听的启停。它记录当前会话代次内新的普通桌面应用激活，核对通知中的应用与当下实际接收键盘事件的前台应用一致，并确认中断条件已解除。该证据与已确认的主入口故障同时成立时，主动显示修复入口。这组证据使用 `NSWorkspace` 的应用激活通知和 `frontmostApplication`，无需双击事件监听权限。过期通知、系统登录界面、休眠前缓存的前台应用均不能提供这一依据。SDK 对会话切入的定义是用户会话切换。它和安全输入都无法单独证明已经解锁。此处也不依赖未公开的锁屏通知名。[AppKit 前台应用](https://developer.apple.com/documentation/appkit/nsworkspace/frontmostapplication) · [应用激活通知](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification) · [Apple 对锁屏状态来源的说明](https://developer.apple.com/forums/thread/850327)

如果返回同一应用时没有产生新的可用证据，保持现有窗口状态，并保留故障供后续交互重新评估。仅当仍有待修复故障、主窗口隐藏且无已知中断时，接受用户通过 Finder 等重新打开已运行应用产生的 macOS `RunEvent::Reopen`。该显式入口复核故障后走同一显示路径，使主快捷键与输入监控同时失效时仍能修复。健康会话沿用原有重开行为。

### 在执行窗口动作前重新核对

让睡眠通知、轮询、监听线程退出、布局刷新和配置更新经过同一判断。故障代次和会话代次共同标识待处理请求。进入中断、配置替换、故障恢复或进程停止时使旧请求失效。输入回调、定时确认以及已经排进主线程的 Toggle、Show 和 Action 在执行时检验所属代次，避免一次完整睡醒后误把旧事件当作新按键。

释放服务锁后才调度主线程。主线程复核当前代次、会话、唯一入口故障和主窗口可见性，对同一次故障最多保留一个在途显示。窗口已可见时保持修复和退出可达；显示失败按现有错误边界处理，后续有效复核仍可重试。已认可的修复显示经统一 `LauncherWindowActions` 执行，保留真实故障的隐藏保护及原有插件所有权检查。对中断时已受理但还未派发的 Action，复用现有失败回执结束该调用，避免 Host 再次就绪时从待处理队列重放；已进入插件执行的调用继续遵循原有生命周期。

正常的显式 Launcher 快捷键仍执行 Toggle，从隐藏的首页恢复输入框，从隐藏的插件页恢复同一实例。只有新的专属快捷键走 Action 分派。通过强制导航首页来掩盖弹窗会丢失插件上下文；在唤醒后延迟固定时间显示则仍可能在锁屏期间抢焦点。

## Risks / Trade-offs

- 用户仅亮屏或系统短暂唤醒 → 保留隐藏状态，待新的桌面交互证据出现时再评估真实故障。
- 权限被撤销期间无法通过双击证明用户已回来 → AppKit 桌面通知与显式重新打开都独立于该权限。
- 快照发布与主线程执行交错，或显示触发新的焦点通知 → 用可控队列验证旧回调失效、重复通知只产生一次显示，以及已完成修复可取消尚未执行的显示。
- 假窗口和时钟无法验证不同 macOS 版本的实际通知顺序 → 在现有 `launcher-shortcuts` Gate 中覆盖事件顺序、缺失通知、重叠中断、窗口调用和页面保持，不把确定性测试视为实机验收。

## Migration Plan

随 Host 更新交付。新状态仅保存在进程内，继续读取现有快捷键文件和插件配置。回滚 Host 即可恢复旧策略，无需改写用户数据。
